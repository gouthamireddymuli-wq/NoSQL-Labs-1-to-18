1. Executive Summary & Objectives

This laboratory investigates multi-document ACID transaction guarantees in MongoDB using PyMongo on a WiredTiger storage engine configured with a replica set (rs0). The core deliverables include:

  • Lab 10.1 (Bank Transfer System): Executing atomic transfers between multiple accounts, enforcing strict rollback on insufficient funds, and implementing exponential backoff retry for transient write conflicts.
  • Lab 10.2 (Inventory Reservation System): E-commerce stock reservation across inventory and orders collections with optimistic concurrency control (OCC), write-conflict detection, multi-threaded stress testing, and throughput (TPS) measurement.
  • Interactive Web Dashboard: A full-stack Flask web application deployed in Docker to demonstrate both transaction workflows in real time.

3. Lab 10.1: Bank Transfer Transaction

3.1 Transaction Workflow

The fund transfer executes within a ClientSession with snapshot read concern and majority write concern:

with session.start_transaction(
    read_concern=ReadConcern("snapshot"),
    write_concern=WriteConcern(w="majority")
):
    # 1. Atomic debit with conditional balance filter
    result = col.update_one(
        {"account_id": from_id, "balance": {"$gte": amount}},
        {"$inc": {"balance": -amount, "version": 1}},
        session=session
    )
    if result.matched_count == 0:
        raise ValueError(f"Insufficient funds in {from_id} (need ${amount:.2f})")

    # 2. Atomic credit
    col.update_one(
        {"account_id": to_id},
        {"$inc": {"balance": amount, "version": 1}},
        session=session
    )

    # 3. Transaction audit ledger record
    col.database["transactions"].insert_one({
        "from": from_id, "to": to_id, "amount": amount,
        "description": description, "timestamp": time.time()
    }, session=session)

3.2 Rollback & Exponential Backoff Retry

  • Automatic Rollback: When an account has insufficient balance, matched_count == 0 triggers a ValueError, cleanly aborting the transaction and leaving all account balances intact.
  • Retry Logic: Transient conflicts (TransientTransactionError) are caught and retried up to 5 times using exponential backoff with jitter: delay = 0.1 * 2^attempt + jitter.

4. Lab 10.2: Inventory Reservation with Deadlock Handling

4.1 Optimistic Concurrency Control (OCC)

To prevent overselling and lost updates without pessimistic locks, the reservation logic uses document versioning:

result = db.products.update_one(
    {"product_id": product_id, "version": item["version"]},
    {"$inc": {"stock": -qty, "version": 1}},
    session=session
)
if result.matched_count == 0:
    raise WriteConflict("Version mismatch - concurrent modification")

4.3 Architectural Comparison

  • Multi-Document Transaction (Implemented): Couples stock decrement with order insertion atomically. Eliminates orphaned inventory decrements upon process failure.
  • Non-Transactional (findAndModify): Yields slightly higher raw TPS due to lower lock overhead, but risks severe state inconsistency if order insertion fails after stock decrement.
