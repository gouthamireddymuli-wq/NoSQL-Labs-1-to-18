System Architecture & REST API Specification

Deep Dive into Multi-Tenant Isolation Tiers, Security Models & Production API Schemas

Shared Collection (Document Key)
Tier 1: High Density / Low Cost

All tenants share a single collection (saas_app.tasks). Every document is tagged with tenant_id.

  • Indexes: Compound index {tenant_id: 1, created_at: -1}.
  • Cost: Minimal RAM, single set of file handles.
  • Risk: Requires software enforcement. If developer writes {_id: id} instead of {_id: id, tenant_id: tenant}, data is exposed cross-tenant.
Collection per Tenant
Tier 2: Logical Isolation

Each tenant receives their own dedicated collection in the same database (e.g., db.tasks_acme).

  • Indexes: Independent per-tenant indexes.
  • Management: Can drop or index an individual tenant without locking neighbors.
  • Trade-off: High collection count leads to namespace and metadata overhead at scale (>10,000 collections).
Database per Tenant
Tier 3: Physical Isolation

Enterprise tenants are isolated into dedicated databases (e.g. tenant_acme).

  • Compliance: GDPR right-to-erasure achieved with instant dropDatabase().
  • Security: Granular database-level MongoDB RBAC users per tenant.
  • Migration: Activity 2 provides the frictionless upgrade path between Tier 1 and Tier 3.
REST API Endpoint Reference
Base URL: http://localhost:5005/api
Method Endpoint Description & Behavior Headers & Query Params
GET /api/health MongoDB connection health, server version, list of dedicated tenant databases. None
GET /api/tenants Returns all active tenants across shared collections and dedicated databases. None
GET /api/tasks Retrieves all tasks scoped strictly to the requesting tenant. X-Tenant-ID: tenant-acme or ?tenant_id=...
POST /api/tasks Creates a new task. Checks rate limiter (10 req/60s). Rejects with 429 if throttled. X-Tenant-ID: tenant-acme, Body: {title, priority, ...}
PUT /api/tasks/<task_id> Updates task within tenant boundary. Enforces compound filter {_id, tenant_id}. X-Tenant-ID: tenant-acme, Body: {status, priority}
POST /api/security/simulate-attack Interactive BOLA security evaluation comparing vulnerable vs secure filters. Body: {task_id, attacker_tenant, mode}
POST /api/rate-limit/test Runs sliding-window rate limit burst test (e.g. 12 calls) in MongoDB. Body: {tenant_id, burst, limit, window}
POST /api/migration/dry-run Executes migration dry-run, reporting candidate documents without writing. Body: {tenant_id}
POST /api/migration/execute Performs live idempotent migration using upsert on (tenant_id, title). Body: {tenant_id}
POST /api/migration/rollback Drops the tenant's dedicated database. Leaves shared collection untouched. Body: {tenant_id}
Example CLI Invocations (cURL)
curl -X POST http://localhost:5005/api/tasks \ -H "Content-Type: application/json" \ -H "X-Tenant-ID: tenant-acme" \ -d '{"title": "Deploy Model", "priority": "high"}'
curl -X POST http://localhost:5005/api/migration/execute \ -H "Content-Type: application/json" \ -d '{"tenant_id": "tenant-acme"}'
