How Migration Idempotency Works

If a network blip or worker crash interrupts the migration halfway through, the operator must be able to re-run it safely from the beginning.

# Upsert keyed on business identity (NOT random _id) target_col.update_one( {"tenant_id": doc["tenant_id"], "title": doc["title"]}, {"$set": doc}, upsert=True )

Because upsert=True is keyed on the natural compound key (tenant_id, title), repeat executions find the document already present and overwrite it in place, keeping the target count constant.

Why the Rollback is Safe & Lossless

A data migration without a rollback path is a one-way door. The Lab 15.2 protocol follows a non-destructive Copy-Then-Verify pattern:

  • migrate_tenant() never deletes documents from saas_app.tasks.
  • Rollback simply executes client.drop_database("tenant_acme").
  • Because the shared collection was never modified, dropping the copy returns the system to the exact baseline state with 0% risk of data loss.
