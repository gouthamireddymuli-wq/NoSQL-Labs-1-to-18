Activity 1: Production Replica Set Deployment

Docker Compose with keyFile Authentication & Bootstrapped Superuser

Intra-Cluster HMAC Enforced
keyFile Authentication vs Client RBAC

keyFile authentication is how replica set members trust each other, not how clients authenticate. Every member shares the same cryptographically secure secret (756 bytes random base64). When nodes exchange heartbeats or sync operations, they use HMAC-SHA verification with the keyfile to prove they are legitimate members and reject any rogue mongod.

Keyfile Path: /etc/mongodb/keyfile
Permissions: 0400 (Read Owner Only)
Verification Mode: HMAC-SHA-256 Intra-Cluster
Order of Operations: Bootstrap Localhost Exception

In production, starting nodes with --auth and --keyFile locks out unauthenticated access. However, MongoDB provides the Localhost Exception: on a freshly initiated cluster with no users in the admin database, local connections are permitted to create the initial administrative superuser.

  1. Generate keyfile: openssl rand -base64 756 > keyfile
  2. Start containers: with --replSet rs0 --auth --keyFile
  3. Initiate replica set: rs.initiate(...) forms the cluster
  4. Create admin user: Superuser created on Primary before auth locks down
  5. Enforce cluster auth: All subsequent queries require credentials
